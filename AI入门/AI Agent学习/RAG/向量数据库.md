## 三、从技术角度看，主要有 4 个区别

**1\. 数据规模与分布式能力**

- Chroma：更适合入门和中小型项目。
- Qdrant：适合生产级向量检索。
- Milvus：适合超大规模分布式向量检索。

注意：这不是绝对的容量排名，实际性能取决于硬件、索引和数据特征。

**2\. 检索方式**

主要有两种：

- 向量检索：根据语义相似度寻找内容。
- 混合检索（Hybrid Search）：同时使用向量相似度和关键词匹配。

例如搜索：

「苹果手机如何更换电池？」

向量检索可能找到：

- iPhone 电池维修指南
- 苹果设备续航优化

关键词检索可能找到：

\- iPhone 电池更换教程

混合检索可以结合两者的优势。

Weaviate、Qdrant、Milvus 等都支持不同形式的混合检索。\[[Best Vector Databases in 2026: A Complete Comparison Guide](https://www.firecrawl.dev/blog/best-vector-databases?trk=article-ssr-frontend-pulse_little-text-block&utm_source=chatgpt.com); [Vector Database Comparison](https://yigtwxx.github.io/awesome-rag-production/docs/vector-database-comparison/?utm_source=chatgpt.com)\]

**3\. 部署方式**

主要分为三类：

| 类型 | 代表 | 特点 |
|--------|--------|--------|
| 独立数据库 | Milvus、Qdrant | 单独部署和维护 |
| 云端托管 | Pinecone | 服务商负责基础设施 |
| 数据库扩展 | pgvector | 在现有数据库中增加向量能力 |
| 嵌入式 | LanceDB | 可以直接集成到应用中 |

**4\. 与传统数据库的关系**

向量数据库并不是要完全取代 MySQL、PostgreSQL、MongoDB。

它们解决的问题不同：

| 数据库类型 | 擅长解决的问题 |
|--------|--------|
| MySQL | 精确查询、关系数据 |
| Redis | 缓存、键值查询 |
| MongoDB | 文档型数据 |
| Elasticsearch | 全文搜索 |
| 向量数据库 | 语义相似度搜索 |

现在不少传统数据库也已经支持向量检索，例如 PostgreSQL、MongoDB 和 Elasticsearch。\[[Vector Databases: Standalone, Managed, Extensions and Libraries](https://codewithsql.com/sql-tools/vector-databases?utm_source=chatgpt.com); [How To Choose a Vector Database Architecture](https://www.splunk.com/en_us/blog/artificial-intelligence/vector-database-architectures.html?utm_source=chatgpt.com)\]

# 四、在 RAG 中，它们是如何工作的？

这是最值得理解的部分。

## RAG + 向量数据库工作流程

**用户提问**

例如：什么是机器学习？

**Embedding 模型**

将问题转换成向量

**向量数据库**

Milvus / Qdrant / Chroma 等

(相似度检索)

找到最相关的知识片段 Top-K

**LLM 大语言模型**

问题 + 检索到的知识

**生成最终答案**

这里需要注意：

向量数据库本身并不负责理解问题、生成答案。

它主要负责的是：**找到与当前问题语义最相关的数据。**

进一步理解企业级向量数据库。

另外，有三个概念建议一起学习：

| 概念 | 作用 |
|--------|--------|
| Embedding | 将文本转换成向量 |
| HNSW | 加速近似最近邻搜索的索引算法 |
| Cosine Similarity | 衡量两个向量方向的相似程度 |

**最后记住一个区别：**

- Embedding 模型：负责把文字变成向量。
- 向量数据库：负责存储和检索向量。
- RAG：负责把检索到的知识交给大模型，辅助生成答案。

这三者是 AI 知识库系统中非常重要的基础组件。
