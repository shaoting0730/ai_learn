稀疏检索（Sparse Retrieval）和稠密检索（Dense Retrieval）是 RAG 中两种非常重要的检索技术。

它们最大的区别是：

- **稀疏检索：** 主要通过关键词匹配来寻找相关文档。
- **稠密检索：** 主要通过语义向量相似度来寻找相关文档。

简单理解：

**稀疏检索看的是「字面上是否匹配」，稠密检索看的是「意思上是否相似」。**

> 苹果手机如何通过脸部识别解锁？

两种检索方式的表现：

**稀疏检索：关键词匹配**

用户问题：苹果手机、脸部识别、解锁

匹配文档中的关键词

文档 1：苹果、Face ID (匹配较多)

文档 2：iPhone、面部识别 (匹配较少)

**稠密检索：语义相似度**

用户问题 → Embedding → 查询向量

比较文档向量与查询向量

文档 2：iPhone 可以通过面部识别解锁 (语义相关)

这里最有意思的是：即使用户说的是「脸部识别」，文档写的是「面部识别」，稠密检索也可能理解它们表达的是相近的意思。

## 二、底层原理有什么不同？

### 1\. 稀疏检索（Sparse Retrieval）

稀疏检索通常使用关键词统计方法，例如：

- TF-IDF
- BM25（目前非常常见）

以 TF-IDF 为例，它会根据词语在文档中的重要程度计算权重。

假设词汇表只有 5 个词：

`苹果、手机、电脑、面部识别、汽车`

一段文本可能被转换成这样的向量：

**稀疏向量示意**

# $$2, 1, 0, 3, 0$$

大量维度为 0，只有少数词语具有非零权重，因此称为稀疏向量。

检索时，系统主要比较查询和文档中的关键词及其权重。

**优点：**

- 擅长精确关键词匹配。
- 对产品型号、专业术语、编号特别有效。
- 不需要额外训练 Embedding 模型。
- 可解释性较好。

**缺点：**

- 不擅长理解同义词。
- 不擅长理解上下文和语义。
- 用户换一种表达方式，可能找不到相关文档。

### 2\. 稠密检索（Dense Retrieval）

稠密检索通常使用 Embedding 模型，将文本转换成固定维度的向量。

例如：

```text
苹果手机如何通过脸部识别解锁？
           ↓
      Embedding模型
           ↓
[0.21, 0.35, -0.12, 0.87, ...]
```

这里的向量可能有 768、1024 或 1536 个维度，通常大多数维度都有非零数值。

系统通过余弦相似度等方式计算向量之间的相似程度。

$$
\text{Similarity}(A,B)=
\frac{A\cdot B}{\|A\|\|B\|}
$$

**优点：**

- 能够理解语义相似性。
- 能够匹配不同表达方式。
- 对自然语言问题比较友好。
- 更适合语义搜索。

**缺点：**

- 对精确编号、型号等信息可能不够敏感。
- 需要 Embedding 模型。
- 向量存储和计算有一定成本。
- 检索效果依赖 Embedding 模型质量。

## 三、稀疏检索 vs 稠密检索

| 对比维度 | 稀疏检索 | 稠密检索 |
|--------|--------|--------|
| 英文 | Sparse Retrieval | Dense Retrieval |
| 核心依据 | 关键词匹配 | 语义相似度 |
| 向量特点 | 大量 0 | 通常大部分非零 |
| 常见算法 | BM25、TF-IDF | Embedding + 向量相似度 |
| 是否需要 Embedding | 不需要 | 需要 |
| 同义词理解 | 较弱 | 较强 |
| 精确关键词 | 较强 | 不一定强 |
| 型号、编号检索 | 较强 | 可能较弱 |
| 自然语言搜索 | 一般 | 较强 |

## 四、Hybrid Search（混合检索）

既然稀疏检索和稠密检索各有优缺点，能不能把它们结合起来？

当然可以，这就是 **Hybrid Search（混合检索）**。

**用户问题**

**稀疏检索**

BM25

关键词匹配

**稠密检索**

Embedding

语义匹配

关键词结果

语义结果

**结果融合（RRF 等）**

**Rerank 重排序**

**LLM 生成最终答案**

举个例子：

用户问：

> iPhone 17 Pro Max 的 A19 Pro 芯片有什么特点？

- 稀疏检索：能够精准匹配 `iPhone 17 Pro Max`、`A19 Pro`。
- 稠密检索：能够找到介绍芯片性能、架构、能效的相关内容。
- 混合检索：综合两种检索结果，提升召回效果。

## 五、在 RAG 学习体系中的位置

把之前学习的 RAG 概念串起来：

| 技术 | 主要解决的问题 |
|--------|--------|
| Native RAG | 如何完成基础检索和生成 |
| Sparse Retrieval | 如何通过关键词检索 |
| Dense Retrieval | 如何通过语义检索 |
| Hybrid Search | 如何结合两种检索 |
| Rerank | 如何重新排列检索结果 |
| Advanced RAG | 如何系统性优化 RAG |
| Modular RAG | 如何灵活组合 RAG 模块 |

**建议重点掌握这条技术链：**

## RAG 检索核心流程

1. **Embedding**
   
   文本转换成向量。
2. **Sparse / Dense Retrieval**
   
   关键词检索与语义检索。
3. **Hybrid Search**
   
   合并不同检索方式的结果。
4. **Rerank**
   
   对候选文档重新评分、排序。
5. **LLM**
   
   根据检索结果生成答案。

这几个概念弄明白，你就基本掌握了 RAG 检索部分的核心技术。
